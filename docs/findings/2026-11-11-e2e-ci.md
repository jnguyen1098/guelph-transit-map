## Implementation

`tests/` is an independent locked Playwright package. The plain-language entry points and coverage boundaries are documented in `tests/README.md`. It archives the selected source commit into one owned temporary base, installs the app lockfile there, replays SHA-checked GTFS data through the real Express app, and uses real Chromium/Leaflet/MapLibre/Bootstrap. Test-only seams fix the server/browser clock, replay upstream GETs, and bind Express to an ephemeral loopback port. App source is never rewritten.

The existing replay strategy was adopted from `review/server-probe.cjs`. Playwright supplies execution, fixtures, reporting, screenshots and traces. Python's standard ZIP implementation builds the fixture archive. The shared capture-manifest helper is vendored unchanged, and the shared UA-normalization function is reused. The automation inventory search found no matching transit CI implementation; its stated blind spots mean that search is not proof of global absence.

Failure reports retain console/exception logs, server logs, upstream request timing, memory/CPU/active-resource samples, screenshots and traces. Twelve route cycles and twelve card cycles check map-layer retention after the first shared SVG renderer initializes. These are bounded functional/resource checks, not a general security audit, a heap-leak proof, or a calibrated performance benchmark.

Temporary browser profiles, npm state, and app state are routed into the owned base. Chromium's reported profile path is checked against that boundary. Child processes stop before cleanup; Python's local manifest import does not write bytecode into source. Intentional failure runs verified screenshot/trace/report production and cleanup. Browser/dependency installations remain as ignored tooling caches. The original November 4 transit observations remain intact; the smaller committed fixture names its selection and original hashes.

`.github/workflows/nightly-transit.yml` uses Node 24, serial upstream `main`/PR18 targets, one worker, zero retries, 20-minute job limits, and seven-day evidence retention. It is scheduled at 03:17 America/Toronto. `hourly-transit.yml` makes six production HTTP GETs at minute :37, with a five-minute limit and two-day retention. Both require the fork repository identity and `contents: read`; neither has a PR trigger or secrets. Push/manual triggers support validation once publishing works. Actionlint 1.7.12, downloaded from its official release and checked against the published SHA-256, accepted both workflows.
